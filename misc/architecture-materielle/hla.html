Assembleur

Le langage assembleur présenté ici, inspiré de High-Level Assembly (HLA), est défini pour un sous-ensemble du jeu d'instructions x86 conçu par Randall Hyde (cf. The Art of Assembly, chapitre "Instruction Set Architecture"). Il comprend les instructions suivantes :

L'architecture matérielle sur laquelle est définie le langage suppose l'existence de huit registres (à l'instar de x86):

  • A (accumulateur)
  • B (base d'index, pour la gestion des tableaux)
  • C (compteur, pour les itérations en boucle)
  • D (pensé pour étendre la précision du registre A)
  • BP (base pointer, pour dépiler lors d'un renvoi de fonction)
  • SP (stack pointer, pour pointer vers le haut de la pile)
  • EFLAGS (voir cmp et les instructions de saut)
  • IP (instruction pointer)

Ces registres peuvent être utilisés comme arguments d'instructions (noms des registres donnés en minuscule). Les arguments peuvent aussi être des constantes ou des adresses mémoire. L'adressage peut être direct, indirect ou indexé. Par exemple, les trois instructions ci-dessous déplacent une valeur depuis la mémoire vers le registre A, selon chacun des modes d'adressage :

  • mov([32], a); utilise directement l'adresse 32 ;
  • mov([b], a); utilise l'adresse stockée dans le registre B ;
  • mov([b+4], a); utilise l'adress à 4 unités de celle stockée dans B.

Chaque registre et chaque adresse mémoire peut stocker un entier de taille arbitraire, ce qui n'est évidemment pas réaliste. Dans un véritable processeur, cet entier serait représenté sur un nombre pré-déterminé de bits (8, 16, 32, 64). Pour simplifier, ici, on ne se préoccupe pas de sa représentation concrète. On fait donc référence à A plutôt qu'aux registres AL, AH, AX ou EAX définis dans x86, par exemple. On met aussi de côté la représentation des entiers négatifs (qui utilise le plus souvent la méthode du complément à deux).

L'adresse 0, en mémoire, correspond au début de la pile. La pile ayant une taille maximale de 32 entiers, l'adresse qui suit (adresse 32) est celle du début du tas, dont la taille est aussi de 32 entiers. Arrive ensuite la mémoire statique (16 entiers), puis le code du programme. Les adresses progressent donc de haut en bas dans le diagramme ci-dessous.

Pour simplifier l'écriture des programmes, les adresses de programmes sont indexées  la première instruction du programme est virtuellement à l'adresse 0, alors qu'elle se trouve en fait à l'adresse 80 (première adresse disponible après la pile, le tas et la mémoire statique).
